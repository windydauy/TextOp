【TextOp 关键差异摘要】
  - 探索噪声初始值更大 (1.0 vs 0.05)，且无 std clamp，训练中 std 可无限增大
  - 单一 learning_rate 1e-3，SONIC actor LR 低一个数量级 (2e-5)
  - max_grad_norm 更松 (1.0 vs 0.1)
  - entropy 系数更小 (0.005 vs 0.01)

【SONIC sonic_g1_only_5point_ori 特有】
  - std_clamp: [0.001, 0.5]，防止探索噪声爆炸
  - Actor/Critic 分离学习率
  - Universal Token + motion reconstruction auxiliary loss
  - 历史观测长度 actor_prop_history_length = 10

================================================================================
五、关键结论
================================================================================

【PPO】
  1. 核心 PPO 超参（clip/gamma/lam/epochs/mini_batches/steps）两者接近。
  2. 最大差异：SONIC 有 std clamp [0.001, 0.5]、更低 init_noise_std (0.05)、
     分离 actor/critic LR、更紧 max_grad_norm (0.1)；TextOp 均无 std 上限。
  3. SONIC 使用 Token + aux reconstruction loss；TextOp 纯 MLP/MNMLP tracking。

【Domain Random】
  1. 摩擦/关节零位/CoM/push 速度范围基本一致。
  2. SONIC 额外：trimesh 地形、wrist+torso 质量随机、更稀疏 push (4~6s)。
  3. Reset pose/velocity/joint 随机化范围两者相同。

【数据增强】
  1. 两者都有 policy obs 均匀噪声 + corruption。
  2. SONIC 额外：10 帧 history、upper body pose 拼接增广、freeze frame；
     TextOp 无 motion-level 增广（random_static 默认关）。
  3. 两者本配置均未启用 PPO symmetry mirror。

7.2 TextOpTracker — commands_multi.py（当前主路径）
────────────────────────────────────────────────────────────────────────────────

【开关与默认配置】MotionCommandCfg:
  enable_adaptive_sampling: False        ← 默认关闭，走 uniform motion 采样
  ads_type: "v1"                         ← v1 / v2 / v3 三种失败率公式
  ads_stable_count: True                 ← 仅当该 motion 本 step 被尝试过才更新计数
  adaptive_uniform_ratio: 0.1            ← 10% 均匀分布混合
  adaptive_alpha: 0.001                 ← EMA 平滑系数（极小，变化很慢）
  adaptive_beta: 0.5                     ← 失败率指数变换
  adaptive_length_weighted: False        ← v1 可选：按 motion 长度加权

【关闭时 (_uniform_sampling)】
  motion_idx ~ Uniform(0, num_motion_files)

【开启时 (_adaptive_sampling) 流程】

  Step 1 — 统计本 batch reset 的成功/失败（按 motion_idx）:
    episode_failed  = termination_manager.terminated
    episode_success = ~episode_failed（含 motion 播完自然结束）
    current_failed_motion_count[m]  += count
    current_success_motion_count[m] += count

  Step 2 — 计算每条 motion 的失败率 p_fail（三种 ads_type）:

    v1: p_fail = failed / sum(failed)           # 全局失败占比
        可选 × file_lengths 再归一化

    v2: p_fail = failed / (failed + success)      # 每条 motion 自身 fail rate

    v3: p_fail = failed / (failed + success)
        p_fail_sample = 1 - (1 - p_fail)^beta   # 强调高失败率尾部

  Step 3 — 采样概率:
    p_fail_sample = p_fail ^ beta（v1/v2）或 v3 公式
    prob = p_fail_sample * (1 - uniform_ratio) + uniform_ratio / num_motion

  Step 4 — 采样 motion:
    motion_idx ~ Multinomial(prob)

  Step 5 — 起始帧（与 adaptive 无关）:
    time_steps ~ Uniform(0, motion_length)      ← 始终随机，不按失败段调整

  Step 6 — EMA 更新全局计数（每 step _update_command）:
    failed_motion_count  ← alpha * current_failed + (1-alpha) * failed_motion_count
    success_motion_count ← 同理
    pfail_total = failed_total / (failed_total + success_total)  → 用于 reward 门控

【旧版 commands.py（单 motion 文件）— bin 级，与 multi 不同】
  - 将一条 motion 均分为 bin_count 段
  - 失败时记录 fail_bin，用 1D conv + exponential kernel 平滑相邻 bin
  - 采样 bin → 映射到 time_steps
  - 更接近 SONIC 的「时间段级」思路，但仅针对单 clip，multi 路径未使用

【TextOp 特点 / 局限】
  + 实现简单，按 motion 文件粒度调 curriculum
  + v2/v3 用 success+fail 比，比 v1 更合理
  + pfail_total 与 reward pfail 门控联动
  - 默认关闭，多数实验可能是 uniform
  - 不调整 clip 内起始时间 → 难段/易段 within motion 不区分
  - 无 failure rate 上界 clip，难 motion 可能 dominate
  - 无 multi-GPU 统计同步

────────────────────────────────────────────────────────────────────────────────
7.3 gear_sonic — motion_lib_base.py（SONIC 主路径）
────────────────────────────────────────────────────────────────────────────────

【开关与默认配置】motion.yaml → adaptive_sampling:
  enable: true
  bin_size: 50                           ← 每 50 帧一个 bin
  sequence_length_agnostic: true         ← 按 motion 内 bin 数归一化权重
  init_num_failures: 1                   ← 初始 failure/ep 计数（避免除零）
  uniform_sampling_rate: 0.1             ← 10% 均匀（同 TextOp uniform_ratio）
  adp_samp_failure_rate_max_over_mean: 50.0   ← 默认 clip 上界
  pre_failure_sample_window: 200          ← 采样时向前偏移，提前练习难段
  use_failure_rate_decay: false          ← 可选：失败率沿 bin 反向传播

  sonic_g1_only_5point_ori.yaml 覆盖:
    adp_samp_failure_rate_max_over_mean: 20   ← 更紧的 clip（比默认 50 保守）

【数据结构 init_adaptive_sampling】
  - 对数据集中 ALL unique motions 预计算 bins
  - 每条 motion 按 bin_size 切分 → adp_samp_bins[motion_id, start, end]
  - adp_samp_frame_to_bin: 每帧 → bin_id（全局稳定索引）
  - adp_samp_bin_weights: 长 bin 权重 × sequence_length_agnostic 归一化

【每 step 统计 update_adaptive_sampling】
  - 输入: failure=reset_terminated, motion_ids, motion_time_steps
  - 定位 bin: frame = length_start[motion] + time_step → bin_id
  - adp_samp_num_episodes[bin] += count / bin_length
  - 若 failure: adp_samp_num_failures[bin] += count × multiplier

【周期性重算 sync_and_compute_adaptive_sampling】
  - 多 GPU: gather episodes/failures → mean
  - failure_rate = failures / episodes
  - 可选 decay: 沿 bin 序列反向传播失败率（类似 GAE）
  - update_adaptive_sampling_probabilities():

      active_rate_clipped = clip(rate, 0, mean(rate) × max_over_mean)
      prob_fail = active_rate_clipped / sum
      prob = prob_fail × (1 - uniform_rate) + uniform × uniform_rate
      prob × bin_weights → 归一化

  - 可选 max_prob_per_bin / max_prob_per_motion 防 catastrophic forgetting
    （默认 yaml 未配置 → 仅用 failure rate clip）

【采样 sample_motion_ids_and_time_steps(n)】
  1. bin_id ~ Multinomial(adp_sampling_active_prob)
  2. time_step ~ Uniform(bin_start, bin_end)   ← bin 内随机帧
  3. 若 pre_failure_sample_window > 0:
       time_step -= randint(0, window)        ← 提前 200 帧起步
  4. 返回 (motion_id, time_step)

【与 PPO 训练循环集成】
  - ppo_trainer.sync_adaptive_sampling(): 每 sync_adaptive_sampling_all_gpus_freq
    步（默认 200）跨 GPU 同步并重算概率
  - im_resample_callback: 可触发 env.resample_motion() 刷新 loaded batch

【SONIC 特点】
  + Bin 级 curriculum：同一 motion 内难段/易段分开加权
  + motion + 起始帧联合自适应
  + failure rate clip (max_over_mean) 防止单一难 clip 垄断
  + pre_failure_window 让 policy 在失败前先练习
  + 多 GPU 同步 + checkpoint 恢复统计
  - 实现复杂，依赖全局 bin 索引与 motion lib 预计算
  - bin_size / window 等超参敏感

────────────────────────────────────────────────────────────────────────────────
7.4 核心公式对比
────────────────────────────────────────────────────────────────────────────────

TextOp (v2, 默认推荐类型):
  p_fail[m] = failed[m] / (failed[m] + success[m] + eps)
  prob[m]   = normalize(p_fail[m]^β) × (1-ε) + ε/M
  time      ~ Uniform(0, len[m])                    # 与 prob 无关

SONIC:
  rate[b]   = failures[b] / episodes[b]
  rate'[b]  = clip(rate[b], 0, mean(rate) × K)     # K=20 (5point_ori)
  prob[b]   = normalize(rate'[b]) × (1-ε) + ε/B_active
  prob[b]  × bin_weight[b]
  (motion, t) ~ prob[b] → bin b → uniform t in [start, end) - offset

7.6 关键结论
────────────────────────────────────────────────────────────────────────────────

1. 粒度不同：TextOp 选「哪条 motion」；SONIC 选「哪条 motion 的哪一段」。
2. TextOp 默认关闭 adaptive；SONIC 默认开启且是训练核心机制之一。
3. SONIC 有 failure rate 上界 clip + pre-failure window，curriculum 更细、更稳。
4. TextOp 的 pfail_total 与 reward/termination 门控绑定，adaptive 统计有下游用途；
   SONIC adaptive 主要服务 motion 采样，与 reward 解耦。
5. 若要把 TextOp 对齐 SONIC：需在 commands_multi 引入 bin 级统计、联合采样
   time_steps，并加 failure rate clip；或启用 SONIC 式 motion_lib 架构。
